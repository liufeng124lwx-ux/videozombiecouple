# 「50 Christmases」内容与评测设计（第二份计划的依据）

- 日期：2026-10-16
- 状态：待用户审阅
- 上级文档：`2026-10-15-christmas-story-design.md`（本文只写新增与改动）；骨架已在 `feat/model-eval` 合入（计划 `docs/superpowers/plans/2026-10-15-multi-story-backbone.md`）
- 依据：即梦实测 `docs/research/2026-10-15-christmas-jimeng-notes.md`

## 1. 目标与边界

### 1.1 要做什么
让圣诞故事的三个场景（`snow-cabin`、`city-flat`、`farmhouse`）都达到可上线的质量：定稿提示词、加「看图描述外貌」步骤和特写候选、做齐场景素材与配乐、在测试站用线上模型评测通过。

### 1.2 已定决策（2026-10-16 与用户确认）
| 决策 | 结论 |
|---|---|
| 首发场景 | 三个一起做 |
| 外貌描述的保存 | 付款后描述；只存本单生成状态，随照片 3 天删除；不进数据库、不写日志；只描述衣着和毛发 |
| 描述的实现 | 新能力 `describe`，走 KIE 看图对话接口，路由表 + 熔断（方案 A） |
| 素材 | 评测脚本在 KIE 上生成（GPT Image 2 + Kling） |
| 配乐 | suno.com，用户的 Suno Pro 订阅期内生成；音效只用 CC0 |
| 贯穿要求 | 每节都写成本与安全合规（用户 2026-10-16） |

### 1.3 不做
场景上线（`live: true`）、页面、定价页、Stripe 商品、隐私政策正文修改——都在第三份计划。宠物版。丧尸片的任何改动。

## 2. 生成流程改动

### 2.1 故事开关
`Story` 加 `describe: boolean`。`CHRISTMAS.describe = true`，`ZOMBIE.describe = false`。丧尸片的步骤、提示词、请求逐字不变（现有快照测试守护）。

### 2.2 圣诞片步骤
```
付款后：describe
  → 第 1 轮：kf:wide ×2、kf:memory ×2、kf:forgetCold ×2、kf:rememberClose ×2（参考图都只有照片）
  → 一次打分，四组各挑一张
  → 第 2 轮：kf:tree（依赖 wide）、kf:forgetWarm（依赖 forgetCold）
  → 第 3 轮：kf:embrace（依赖 tree）
  → 镜头 1–3、5–8（4、9 是场景成片）→ 合成
```
- `forgetCold`、`rememberClose` 的 `candidates` 由 1 改为 2，参考图只用本人照片（见 §3），不再依赖 wide，所以能放进第 1 轮。
- 所有关键帧依赖 `describe`。仍是现有通用流程的单个打分步骤（id 为各打分帧 id 相连）；丧尸片仍是 `score:AC`。
- 最慢一条线变短：describe → 第 1 轮 → 打分 → forgetWarm → 镜头 6 → 合成。

### 2.3 `describe` 步骤
- **能力**：`describe`（文本）。路由：主力 `claude-haiku-5-5`，备用一个 Gemini Flash 型号（以评测时 KIE 目录实际可用者为准，写进 `routes.ts`）。KIE 同步接口按模型 schema 的 path 调用；读 `code` 判成败。
- **输入**：两张照片的短期签名链接 + 固定指令：只描述看得见的头部遮盖、头发（长度、颜色、发型或光头）、胡须、眼镜；不写年龄、宗教、族裔、国籍、健康、身体特征；固定输出两行 `IMAGE 1: …` / `IMAGE 2: …`。
- **校验（代码里，确定性）**：
  - 每行 ≤ 120 字符，只保留 `IMAGE 1:` / `IMAGE 2:` 两行；
  - 规范化：`hijab`、`niqab`、`turban` 等宗教性衣着名换成中性描述（`headscarf`、`head wrap`）；
  - 出现禁止词（宗教、族裔、国籍、肤色以外的种族推断、健康、残障、年龄数字）→ 该行作废；
  - 作废或缺行 → 该人的描述为空。
- **失败**：换备用模型；仍失败则描述为空、继续生成（已付款的单不因描述失败而失败），记录失败种类（不含描述原文）。
- **使用**：关键帧提示词里出现该人时插入其描述；描述为空时不插任何外貌句（不回退到会出错的通用句式）。

## 3. 提示词定稿规则（来自即梦实测）

| 关键帧 | 参考图 | 规则 |
|---|---|---|
| wide | 照片 1、2 | 「late seventies, unmistakably elderly…」衰老句；每人描述行；不写「保留头发/头巾/胡子」的通用句；忘记的一方「gazing out at the snow, not at the other person」 |
| forgetCold / rememberClose | **只用本人照片** | 衣服、房间、光线写成文字；「the same gender as IMAGE 1」；本人描述行；头肩特写 |
| forgetWarm | 本人照片 + forgetCold 选中帧 | 同构图换暖光，「the same gender」 |
| memory | 照片 1、2 + 挂饰 | 「face, hair, age and gender exactly as in IMAGE n」；描述行（年轻） |
| tree / embrace | 照片 1、2 + 前一帧（tree 另加挂饰） | 逐人写清脸来自哪张、衣服来自哪张；性别；描述行；「only this one heart ornament on the tree」 |

- 即梦调试：每次新建对话；按提示词文字匹配记录；人像 p01、p03、p06、p07、p09；每张关键帧至少 3 组人像通过才定稿。
- 镜头提示词只在评测中用 Kling 实测。
- 提示词版本：圣诞 `c1`；订单的 `prompt_version` 按故事记录（修最终审查发现：圣诞单记成了丧尸版本号）。

## 4. 场景素材与配乐

| 素材 | 数量 | 生成 |
|---|---|---|
| `ornament.jpg` | 三个场景共用 1 张 | GPT Image 2，2 候选 |
| `hands.mp4`（镜头 4） | 三个场景共用 1 段 | 关键帧 2 候选 + Kling 5 s |
| `window.mp4`（镜头 9） | 每场景 1 段 | 关键帧 2 候选 + Kling 5 s |
| `music.m4a` | 每场景 1 条，32 s | suno.com（Pro 期内）+ ffmpeg 音量自动化（0:10–0:13 静音，0:20 鼓点）+ CC0 音效 |

- 共用素材在 catalog 里让三个场景指向同一 key（`stories/christmas/shared/…`），`deploy.sh` 照常上传。
- `assets/stories/README.md` 逐项记录：模型、日期、提示词、（配乐）Suno 歌曲 id 与订阅状态、（音效）CC0 来源链接。

## 5. 评测

| 轮次 | 内容 | 预算 |
|---|---|---|
| R0 | `describe`：12 张人像 × 主力/备用 | ≈ $0.05 |
| R1 | 关键帧：5 组人像 × 3 场景（GPT Image 2）+ 场景素材 | ≈ $2.5 + $1.6 |
| R2 | 完整成片：snow-cabin 3 组 + city-flat 1 组 | ≈ $8 |
| R3 | 完整成片：farmhouse 2 组 + city-flat 2 组 | ≈ $8 |

合计 ≈ $20，每轮 ≤ $10（CLAUDE.md）。改提示词后重跑受影响部分，事先报预计花费。

**验收（每个场景）**：选中帧性别画反 0 次；头巾/胡子/光头保留 100% 且不凭空添加；年轻回忆人脸相似度中位数 ≥ 0.6；老年帧相似度只记录，用户盲看 5 组中 ≥ 4 组认得出；tree/embrace 只有一颗挂饰；镜头 1、2、6 不变形、镜头 5 树灯亮起、镜头 7 白闪自然；每单实测模型费 ≤ $2.3；p90 耗时 ≤ 10 分钟；用户看 3 条完整样片通过。结论写入 `docs/model-eval.md` 圣诞章节。

## 7. 安全合规

- **外貌描述**：存在 `state.appearance`（DO 存储），不进同步到 D1 的 `steps`/`picks`，不进 `StoryView`，不写日志/Sentry；照片到期清理时一并清空。测试：D1 行里查不到描述；到期后状态里没有描述；报错与日志里不含描述原文。
- **敏感推断**：只描述衣着与毛发；宗教性衣着名称规范化为中性词；禁止词整行作废（确定性代码 + 测试）。
- **新增数据处理方**：照片发给 kie.ai → Anthropic（备用 Google）做外貌读取。上线前必须更新隐私政策（读取衣着发型、仅用于生成、随照片删除、处理方列表加 Anthropic），列入第三份计划的上线清单，未更新不得切上线。
- **生物特征**：描述不是人脸几何数据；打分仍只在 composer 内存中进行；伊利诺伊州仍只开放宠物版（圣诞片无宠物版，IL 用户下不了圣诞单）。
- **评测数据**：只用 AI 合成人像；产物在 git 忽略目录；评测密钥与线上隔离、不打印；按单排队避免触发 KIE 每小时额度（433）。
- **素材授权**：每个素材与配乐有来源记录；不用 KIE 的 Suno 接口；即梦结果只用于调试，不上线。
