# 多语言：西语、葡语、法语（2026-10-17）

## 为什么
ChatGPT 带来的流量里有非英文页面的访问，哥飞群里反馈 es、pt、fr 流量明显（2026-10-17）。总设计 §1.3 原本只做英文、保留 i18n 结构；这次把结构用起来。所有者说「直接开工」，以下取舍都是实现方的决定，所有者可推翻。

## 范围
- 语言：`es`（拉美中性西语，tú）、`pt`（巴西葡语，você）、`fr`（法国法语，tu）。英语仍是 x-default。
- 翻译的页面（`TRANSLATED_PAGES`，`packages/catalog/src/pages.ts`）：首页、三个故事落地页、AI Zombie Filter、Halloween 博客、价格页，以及工具自己的 `/story`、`/account`（noindex，但付款后用户落在这里，要保持同一种语言）。
- 不翻译：法律页（隐私、条款、退款、DMCA、About、Contact）。英文是有约束力的文本；外语页的页脚直接链到英文法律页，用英文名称。
- 成片本身不变：片中两行字和片尾标题仍是英文。每个外语落地页的 FAQ 都如实写明这一点。
- 不做：本地化 slug（沿用英文 slug，`/es/ai-christmas-video`）、邮件和 Stripe 结账页翻译（Stripe 按浏览器语言自动显示）、llms.txt 外语版、404 外语版、示例图 alt 文本。

## 做法
- URL：`/<locale>/<英文 slug>`，首页 `/es`。hreflang 每页列出全部语言 + x-default（已有逻辑）。站点地图按语言分文件（已有）。
- 文案：`packages/i18n/src/{es,pt,fr}.ts` 与 `en.ts` 同键、同 `{param}`、不含数字（测试守护）。页面正文在 `apps/web/src/content/pages/<locale>/`，数字仍只用 `{{catalog.key}}` 和 `<F k=…/>`。
- 浏览器包只带英文：外语页把本语言的字符串内联成 `globalThis.__vzcMessages`（`BaseLayout.astro`），岛屿按 `<html lang>` 读取；缺失时回落英文而不报错。
- 构建时：`[...path].astro` 在渲染前 `setLocale(locale)`，不传 locale 的 `t()` 都用页面语言。依赖 Astro 一次只渲染一个页面（`build.concurrency` 默认 1）；404 页显式切回英文。
- 链接：`localizedPath(page, locale)` 有译文就链译文，否则链英文；工具里写死的 `/story`、`/account`、`/pricing` 走 `localePath()`。
- 页脚加语言切换（链到同一页的其他语言）。

## 成本
- 翻译由编码代理完成，无 API 费用；没有调用 KIE 或任何付费模型。
- 每个外语页多约 9 KB（gzip）内联字符串；英文页不变，岛屿包体积不变（size-limit 守护）。
- 构建页面数约 ×2.6（OG 图同比增加），构建时间相应增加；Cloudflare 静态托管无额外费用。
- 后续维护：每次改英文文案都要同步三种语言，否则测试失败（键不齐）。这是持续成本。

## 安全与合规
- 法律页只有英文，避免翻译版与英文版条款不一致；外语页的隐私段落是英文隐私政策的忠实翻译，没有新增承诺。
- 价格、保留天数等数字仍只来自 catalog，翻译不可能写错数字。
- 不收集新的数据；分析事件已带 `lang`。
- 成片为英文的事实在每个外语落地页 FAQ 中披露，避免误导购买。

## 上线后
- Search Console 提交新站点地图 `sitemap-es.xml`、`sitemap-pt.xml`、`sitemap-fr.xml`（站点地图索引会自动列出）。
